## 2. Version Marker Strategy (`@icu-version-update:`)

Instead of hard-coding file paths and line rules in the Python script, files opt into version updates via a comment marker containing `@icu-version-update:` followed by a **line template** with `{variable}` placeholders:

```text
<comment_start> @icu-version-update: <line_template> [<comment_end>]
```

* **Supported comment styles**: `// ...`, `# ...`, `/* ... */`, `<!-- ... -->`, `; ...`, `REM ...`.
* **Available template variables**:
  * `{major}`: Major version integer (e.g. `79`)
  * `{prev_major}`: Previous major version integer (`major - 1`, e.g. `78`)
  * `{minor}`: Minor version integer (e.g. `0` for front-load, `1` for initial RC/GA, `3` for `78.3`)
  * `{patch}`: Patch version integer (e.g. `1` for front-load, `0` for RC/GA)
  * `{build}`: Build version integer (`0`)
  * `{ver_short}`: `f"{major}.{minor}.{patch}"` if `patch > 0` else `f"{major}.{minor}"` (e.g. `79.0.1` or `79.1`)
  * `{ver_4part}`: `f"{major}.{minor}.{patch}.{build}"` (e.g. `79.0.1.0` or `79.1.0.0`)
  * `{maven_ver}`: `f"{ver_short}-SNAPSHOT"` (Front-load & RC) or `f"{ver_short}"` (GA)
  * `{gh_rel_ver}`: `f"{ver_short}rc"` (RC) or `f"{ver_short}"` (Front-load & GA)
* **Matching & Replacement**:
  * The script converts `<line_template>` into a regex (replacing placeholders with value-matching patterns) and searches within a small lookahead window (up to 8 lines after the marker, allowing markers to be placed above heredoc blocks like `cat <<_ACEOF` in `icu4c/source/configure`).
  * It preserves the target line's indentation and line ending (`\n` or `\r\n`) and replaces the line content with `<line_template>` formatted with the new version variables.
  * If no line within the lookahead window matches `<line_template>`, the script fails immediately with the file path and line number.

### B. Maven `pom.xml` Files (Updated exclusively via `mvn` CLI calls)

The script does **not** edit any `pom.xml` files directly; instead it invokes Maven:

1. **Update parent version in standalone tool POMs** (`tools/cldr/cldr-to-icu/pom.xml` and `tools/release/java/pom.xml`):
   ```sh
   mvn versions:update-parent -DparentVersion={maven_ver} -DskipResolution=true -DgenerateBackupPoms=false -f tools/cldr/cldr-to-icu/pom.xml
   mvn versions:update-parent -DparentVersion={maven_ver} -DskipResolution=true -DgenerateBackupPoms=false -f tools/release/java/pom.xml
   ```
2. **Update root `pom.xml` and all 21 `icu4j/**/pom.xml` modules**:
   ```sh
   mvn versions:set -DnewVersion={maven_ver} -DgenerateBackupPoms=false
   mvn versions:set-property -Dproperty=icu.major.version -DnewVersion={major} -DgenerateBackupPoms=false
   ```

## 4. Script Location & Decisions

1. **Script location**: `tools/scripts/icu_version_update.py` (using `tools/py/libs/` modules: `icudirs`, `icufs`, `iculog`, `icuproc`).
2. **CLI flags**: Phase-based flags (`--frontload <ver>`, `--rc <ver>`, `--ga <ver>`, plus optional `--dry-run` and `--skip-maven`).
3. **`PACKAGE_VERSION` in `icu4c/source/configure`**: Uses `{ver_short}` (e.g. `'79.1'`, without `rc`).
4. **Documentation**: Update `docs/processes/release/tasks/versions.md` to document `tools/scripts/icu_version_update.py` and the `@icu-version-update:` marker syntax.
